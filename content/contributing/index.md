## 内容在哪里

下面的路径**相对于本站源码仓库根目录**，不是部署服务器目录。页面正文使用 Markdown，文件顶部 `---` 包围的部分是页面配置。

| --- | --- |

| 项目展台 | `content/projects/index.md` |
| 文章与活动列表 | `content/posts/_index.md` |
| 主页共建说明 | `content/posts/build-together/index.md` |

普通正文修改不需要接触部署配置、后台权限或游戏服务。首页布局与主题配置的修改，请先在仓库中说明需求，避免为一段内容另建一套组件。

## 从修改到提交

{{% steps %}}

### 先确认事实和公开范围

说明信息来自哪里、目前是否仍有效。历史照片标注历史背景；人物信息取得本人同意；项目链接确认属于协会，不把个人实验冒充团队成果。

### 找到页面，控制范围

先改最相关的一个文件，保留已有路由。文章需要标题、真实的整理或发布日期、简短说明与正文。`content/posts/_index.md` 已通过 `cascade` 为子页指定 `type: blog`，新增文章放在该目录下即可沿用文章皮肤；手册同理继承 `type: docs`。

新文章可使用 `content/posts/简短英文标识/index.md` 这样的页面资源包，把该文章获准公开的图片与正文放在一起。不确定标题或地址时，先讨论再重命名，避免已有链接失效。

### 检查读者实际看到的内容

按照仓库 README 的方法本地预览。查看正文、链接、图片替代文字、手机宽度与深浅色；确认占位标记没有被摘要或卡片隐藏。若无法完成某项检查，在 PR 中如实说明。

### 提交供人审阅的修改

用一条清楚的提交说明概括变化，在 PR 中说明修改原因、来源与影响页面。操作示例见[Git 入门](/docs/git/)。只报告实际完成的检查，不写未经验证的“已通过”。

## 怎样替换占位内容

### 活动示例 → 正式活动文章

`content/posts/activity-example/index.md` 是明确标注的日程示例。真实活动应在 `content/posts/` 下**新建独立文章**，使用已核实的主题、日期、参与方式与公开联络信息；不要把示例文章的发布日期当成活动日期。若以后不再保留示例，应同时更新引用它的手册与方向页面。

正式发布前核实场地或线上安排、人数规则、报名信息用途，以及照片和录屏授权。缺少关键事实时保留“待补充”标记，不借用旧活动链接填空。

### 方向介绍 → 补充真实成员档案

目前四个详情页介绍工作方向，不代表四位成员。成员资料应在取得本人同意后新增独立页面资源包，填写经过确认的公开昵称、简介和链接；图片应得到授权。不要把现有方向页标题改成姓名，却留下不属于该成员的介绍。

主题贡献者皮肤会读取页面资源包内匹配 `feature` 或 `avatar` 的图片。目前 `feature.png` 是协会 Logo，用于方向标识，并非个人头像。新增真实档案之前，需与维护者确认方向页和成员页如何共同展示。

### 新项目 → 补充真实入口

提供项目名称、一句话用途、协会关联、当前维护状态、真实体验或仓库地址，以及图片授权。没有上线就不要写“已上线”，源码需要权限就明确说明；不公开控制面板、凭据或内部管理地址。

## 沿用已有短代码

本站使用 Hextra 0.13 的原生组件。现有页面已给出可直接参考的用法：

- `about`、`projects`：`cards` 与 `card` 组织入口。
- `join`：`tabs` 内使用带 `name` 的 `tab` 区分参与起点。
- `docs` 与本页：`steps` 配合三级标题表达流程。
- `join`：`details` 收起完整海报。
- 各栏目的 `callout`：提示来源、权限与内容占位。

优先复用邻近页面的写法，不添加无法确认存在的图标、外部人物头像或假账号。需要新增素材时，注意压缩体积、补充替代文字，并保留可说明的公开来源。
